# プロンプトスタイルガイド

Version: 1.0

Status: Active

---

# 目的

このドキュメントは、AI Second Brain 全体でプロンプトをどう設計すべきかを定義する。

プロンプトは第一級の資産とみなす。

ソースコードと同じ水準の注意をもって扱うべきである。

すべてのプロンプトは次であるべきである。

* 理解しやすい
* 再利用できる
* 保守しやすい
* 可能な限りモデル非依存

---

# 中核となる考え方

プロンプトは知識を生成しない。

プロンプトは **Knowledge Object** を有用な出力へと変換する。

Knowledge Object が常に source of truth（正本）である。

Knowledge Object が利用できるなら、生のユーザー入力に直接依存するプロンプトを設計しては
ならない。

---

# プロンプトの構成

すべてのプロンプトは、同じ論理構造に従うべきである。

```text
役割（Role）

↓

目的（Goal）

↓

文脈（Context）

↓

入力（Input）

↓

制約（Constraints）

↓

出力形式（Output Format）
```

この構造は、異なる AI モデル間での一貫性を高める。

---

# プロンプトのレイヤー

プロンプトは 3 つのレイヤーに分けるべきである。

## 1. システムプロンプト

長期的な振る舞いを定義する。

例：

* 教育的なトーン
* 視覚的な一貫性
* 執筆の原則

めったに変えるべきではない。

---

## 2. タスクプロンプト

現在のタスクを定義する。

例：

* イラストを生成する。
* Markdown を作る。
* 概念を抽出する。

機能ごとに変わる。

---

## 3. データプロンプト

実際の Knowledge Object を含む。

構造化された情報のみを含むべきである。

ここにビジネスロジックを埋め込んではならない。

---

# Knowledge Object を最優先に

可能な限り、プロンプトは生テキストではなく Knowledge Object を消費すべきである。

好ましい流れ：

```text
生の入力

↓

知識の抽出

↓

Knowledge Object

↓

プロンプト

↓

出力
```

これにより、生成されるすべての成果物の一貫性が保たれる。

---

# プロンプト設計の原則

## 単一責務

1 つのプロンプトは 1 つの問題を解くべきである。

要約・可視化・分類・メタデータ生成を同時に行うプロンプトは避ける。

---

## 明示的な指示

暗黙の前提より、明示的な指示を好む。

悪い例：

「これをうまく説明して。」

良い例：

「この概念を、機械学習に馴染みのあるソフトウェアエンジニア向けに説明して。」

---

## 構造化された出力

可能な限り、構造化された出力を要求する。

好ましい形式：

* JSON
* Markdown
* YAML

創造性を求める場合を除き、自由形式の出力は避ける。

---

## まず決定論的に

新しさより一貫性を優先する。

同じ Knowledge Object は、複数回の実行で似た出力を生むべきである。

---

# 教育プロンプトの原則

教育プロンプトは、次に答えるべきである。

* それは何か？
* なぜ重要か？
* どう動くか？
* 既存の知識とどうつながるか？

不要な専門用語は避ける。

概念的な明快さを優先する。

---

# イラストプロンプトの原則

イラストは「教える」べきである。

決して装飾してはならない。

イラストは次を行うべきである。

* 複雑さを単純化する
* 関係を明らかにする
* プロセスを説明する
* 重要な概念を強調する

好ましい視覚スタイル：

* 手描き
* やわらかい色
* 白背景
* 教科書調
* 情報が豊富
* 視覚的に落ち着いている

---

# Markdown プロンプトの原則

Markdown は、AI なしでも価値を持ち続けるべきである。

すべてのノートは次を含むべきである。

* Summary
* Background
* Illustration
* Key Takeaways
* Related Notes
* References
* Tags

簡潔なテクニカルライティングを用いる。

---

# プロンプトの再利用

プロンプトの重複を避ける。

複数のプロンプトが共通の振る舞いを持つときは、

共通の指示を再利用可能なテンプレートに切り出す。

---

# モデル非依存

プロンプトは、可能な限りモデル固有の振る舞いに依存しないようにすべきである。

同じプロンプトが次で動くべきである。

* ChatGPT
* Claude
* Gemini

わずかな調整は許容する。

---

# プロンプトのバージョニング

重要なプロンプトはすべて、次を含むべきである。

* バージョン
* 目的
* 期待する入力
* 期待する出力

プロンプトの変更は、ソースコードと同様にレビューすべきである。

---

# 長期ビジョン

プロンプトエンジニアリングは AI Second Brain の中核能力である。

ゴールは、あらゆる AI タスクがモジュラーで、テスト可能で、保守しやすい、再利用可能な
プロンプトのエコシステムを築くことである。

プロンプトは、アプリケーションコードの中に埋め込むのではなく、アーキテクチャと一緒に
進化させるべきである。
