# ADR 0014: 既存ノートの自然言語リビジョン（読み戻し・部分更新）

- Status: Accepted
- Date: 2026-08-30
- Deciders: Project owner (ttk1010), Lead Software Engineer (Claude Code)

## Context

ノートは一度生成したら終わりで、後から直す手段が `asb --overwrite`（フル再生成）しかなかった。「要約をもっと易しく」「背景を厚く」「イラストを別テイストで作り直して」のように、**既存ノートを自然言語で部分的に改善**したい（Issue #29, GH #54）。KO は永続化していない（ADR 0005）ため、改善に必要な現在値をどう得るかが論点だった。

## Decision

新コマンド `asb-revise "<対象>" "<指示>"` を追加する。フル再生成せず、狙った部分だけ改善する。

### 状態は Markdown から読み戻す（KO は永続化しない）

ADR 0005 を維持し、KO を JSON 保存する方向には倒さない。改善に必要な現在値（対象セクションの本文、イラストのパス、タイトル、言語）は **ノートの Markdown から読み戻す**。軽量で、既存の知識データ（Vault）以外に状態を増やさない。

### テキストは「該当セクションだけ安全置換」

改善可能な本文セクションは `Summary` / `Background` / `Key Takeaways`。`markdown.sections`（`linker/related.py` の方式を一般化）で **対象セクションの本文だけ**を LLM 執筆結果に差し替える。フロントマターや他セクション、イラスト埋め込みは不変。

### イラストは既存画像を参照に `images.edit` で作り直す

ノートに埋め込まれた画像を **参照画像として `images.edit`** に渡し（ADR 0012 の知見）、テイストを保ったまま指示どおり描き直す。ファイル名は据え置き（#39 と同じく埋め込みリンク不変）。当面は主イラスト1枚が対象（複数ページの一括改善は将来）。

### 対象は自動判定＋明示フラグで上書き

既定では指示文から LLM が対象（セクション or イラスト）を判定。`--section NAME` / `--illustration` で強制指定できる（両者は排他）。

### 履歴は Vault の Git に委ねる（上書きのみ）

版管理用のバックアップは作らず、**上書きのみ**。Vault は Git 管理なので差分・巻き戻しはそこで足りる。

### トリガーは CLI に集中（Telegram は後回し）

まず `asb-revise`（`asb-inbox` / `asb-digest` / `asb-link` と同じ独立 console script）に集約する。Telegram 自然文からのリビジョン連携は別 Issue に切り出す。

## Consequences

- 既存ノートに対し、狙ったセクション/イラストだけを低コストに改善でき、他部分は壊れない。
- フル再生成（全 API 再実行）を避けられる：テキスト改善は LLM 1〜2 回、イラスト改善は画像 1 回。
- KO 非永続（ADR 0005）を維持。状態は Vault（知識データ）に一元化。
- `VaultWriter.find_note`（タイトル/ファイル名/source でノート特定）と `markdown.sections`（汎用セクション置換）を追加。#39 の in-place 方針・#41 の参照画像編集を再利用。
- 複数ページイラストの一括リビジョン、Telegram 連携、`Related Notes`/`References` の編集は本 ADR の対象外（将来拡張）。

## Alternatives considered

- **KO を永続化して復元を厳密化**：強力だが ADR 0005 を覆す大きな設計変更で、#29 の目的（部分改善）には過剰。読み戻しで十分なため不採用。
- **`asb revise` サブコマンド化**：既存 `asb` は単一コマンド。サブパーサ化は既存 UX を壊す。独立 console script（リポジトリの慣行）を採用。
- **明示フラグ必須**：確実だが毎回指定が要る。自動判定＋上書きフラグの方が手軽。
