# ADR 0010: 月次ニュースダイジェスト（ledge.ai アクセスランキング → 1枚のイラスト）

- Status: Accepted
- Date: 2026-07-26
- Deciders: Project owner (ttk1010), Lead Software Engineer (Claude Code)

## Context

その月の主要な AI ニュースを1枚のイラストで俯瞰したい（Issue #39）。既存の News ノートは手動キャプチャした一部にすぎず母集団が偏るため、ソースにしない。ledge.ai トップの「アクセスランキング（30日間）」＝直近30日のアクセス上位 TOP10 を、既製の重要度指標として使う。

論点：ランキングの取得手段（ADR 0004「ヘッドレス不採用・構造化抽出」との整合）、知識タイプの追加（ADR 0007 の前例）、イラストの構図とテキストの扱い。

## Decision

### A. ランキングは `window.__NUXT__` 埋め込みペイロードから静的抽出（ヘッドレス不採用を維持）

30日ランキングは SSR マークアップの `<a>` には無く、インラインの Nuxt 2 IIFE ペイロード（`window.__NUXT__=(function(...){...}(...))`）に `monthlyAccessRankings:[...]` として入っている。Nuxt 2 は重複値を関数引数参照にミニファイするため、`RankingFetcher` は **IIFE の引数環境（param↔value）を復元し、各記事の title/slug をフィールドレベルの参照まで解決**する。これにより httpx の GET だけで TOP10 を取得でき、**ヘッドレスブラウザは不要**（ADR 0004 を維持）。ledge.ai 固有・脆く、壊れたら空リストを返して呼び出し側が graceful degrade する（ADR 0004/0009 が受容する保守コスト）。

### B. 「ダイジェスト」を知識タイプとして追加（ADR 0007 に倣う）

`SourceType.DIGEST` と最小の `DigestData`（`period`, `items:[{rank,title,url,summary}]`）を追加。KO を介して Markdown ノートとイラストの両方を生成する（ADR 0001「イラストは生入力から直接作らない」を順守）。`source = period`（例 "2026-08"）なので同月は冪等。保存先は `08 Digests`。

### C. 対象は「直近30日ローリング」、一文要約はタイトル起点

対象期間はランキングそのまま＝**直近30日ローリング**。`--month` はノートのラベル／冪等キーのみ（既定は実行月）。各記事の一文要約は**タイトルから生成**し、本文フェッチは行わない（安価）。重要度判定はアクセス数で無料、画像は1枚。

### D. イラストは「ハイライト＋ミニ一覧」、テキストは役割分担

構図は上位1〜3を主役、残りを番号帯で並べた俯瞰（16:9、既存の hand-drawn テイスト）。生成画像は日本語の細かい文字が崩れるため、**画像内は番号＋数語の短ラベルに限定し、正確な一文要約は Markdown ノート側に置く**（方式1＝役割分担）。教育設計（Educational Planner）は digest では省略し、構図は固定。

### E. 経路

手動 CLI `asb-digest`（`--month` / `--top` / `--no-image` / `--overwrite`）を正とし、月次実行は cron/launchd 手順を docs 化（ADR 0006 の常駐なし思想）。#33（個別 KO 生成）とは別経路（本 ADR は俯瞰ダイジェスト）。

## Consequences

- ledge.ai の30日 TOP10 から、ノート（順位・タイトル・URL・一文要約・所感）＋イラスト1枚が `08 Digests` に生成される。ヘッドレス不要で ADR 0004 と整合。
- KO スキーマが1フィールド（`digest`）増える（任意・digest 以外は None）。ADR 0007 と同じ扱い。
- ランキング抽出は ledge.ai の Nuxt シリアライズに依存し、サイト変更で壊れうる（graceful degrade）。将来サイトが増えたらソース別アダプタを足す。
- 画像内テキストを完全に正確にしたい場合は、将来「背景生成＋実テキスト合成」（方式2）を追加できる（本 ADR では採用しない）。

## Alternatives considered

- **ヘッドレスブラウザでレンダリング後に DOM の 10 アンカーを取得**：確実だが ADR 0004 に反し重い。IIFE 静的解決で回避。
- **1ヶ月全記事を走査して重要度を自前判定**：重く、アーカイブのページ送り実装が要る。ランキング（アクセス数）を既製の重要度指標として採用。
- **一文要約を各記事の本文フェッチから生成**：精度は上がるが 10 回のフェッチ＋LLM。タイトル起点を既定にし、本文フェッチは将来オプション。
- **画像内に一文要約を焼き込む**：崩れやすい。役割分担（画像＝短ラベル／ノート＝要約）を採用。
